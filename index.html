Engineering

How I build

Practical decisions that make a Roblox system easier to test, secure, and extend.

01

Server ownership first

Damage, rewards, purchases, and progression are validated on the server. The client requests an action; it does not decide the result.

02

State is explicit

Combat, rounds, and player lifecycles use named states and controlled transitions instead of scattered boolean flags.

03

Data has a lifecycle

Profiles are loaded, reconciled, locked to one session, and saved deliberately, with failure paths handled before new features depend on them.

04

The handoff stays readable

Rojo and Git keep source files reviewable. Modules are grouped by responsibility so another developer can continue the work.
